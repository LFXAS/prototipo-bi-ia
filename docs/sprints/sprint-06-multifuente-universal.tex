\section{Resumen ejecutivo}

El Sprint 6 elimina la selección global de una única base y convierte la fuente de datos
en parte explícita de cada artefacto. Una organización puede mantener varias conexiones
SQL Server habilitadas y ejecutar, para cada una, el mismo recorrido: captura de metadatos,
catálogo, formulación, viabilidad, propuesta, aprobación, ETL, conciliación y analítica.

AdventureWorks2022 y WideWorldImporters se usaron como casos de contraste, no como
personalizaciones. El código no decide por el nombre de la base, tabla o columna. La
selección se apoya en estructura, función semántica, tipos, claves, relaciones declaradas,
granularidad y fórmulas controladas.

\notebox{El catálogo no lo construye libremente la IA. El analista administra la orientación
de negocio; la plataforma descubre evidencia técnica por fuente; el LLM interpreta y
propone; y validadores determinísticos aceptan o rechazan cada referencia.}

\section{Objetivo, alcance y definición de terminado}

\subsection{Objetivo del incremento}

Permitir que una misma empresa opere varias fuentes al mismo tiempo, sin desactivar una
para consultar otra y sin mezclar metadatos, propuestas, ejecuciones o resultados.

\subsection{Alcance entregado}

\begin{itemize}
  \item selector persistente de fuente en el espacio de trabajo;
  \item conexiones probadas y habilitadas de forma independiente;
  \item instantáneas, catálogos, propuestas, ETL y analítica filtrados por conexión;
  \item restauración idempotente de WideWorldImporters para la demostración;
  \item detección universal de ventas, fecha, producto, cliente, territorio y costo;
  \item rechazo de rutas de auditoría y evidencia ajena al contexto comercial;
  \item etiquetas descriptivas en dimensiones, filtros y gráficos;
  \item documentación y pruebas automatizadas del contrato multifuente.
\end{itemize}

No se incluyeron pronósticos, combinación de hechos entre bases ni conectores distintos de
SQL Server. Estas extensiones requieren contratos y pruebas propias.

\subsection{Definición de terminado}

\begin{enumerate}
  \item dos bases pueden permanecer habilitadas simultáneamente;
  \item toda petición nueva incluye el identificador de conexión;
  \item una instantánea no puede usarse con otra conexión;
  \item el catálogo de una fuente no altera el de otra;
  \item una propuesta viable no pierde requisitos porque el LLM los omita;
  \item el ETL lee la fuente asociada a la propuesta aprobada;
  \item la conciliación produce diferencia cero y la analítica muestra procedencia;
  \item código, especificación, manual, tesis, bitácora e informe compilan y pasan CI.
\end{enumerate}

\section{Diseño de la solución}

\subsection{Contexto explícito de fuente}

El contrato dejó de depender de una conexión activa global. La tabla de conexión indica si
una fuente está habilitada y probada; el contexto elegido acompaña cada consulta. La
instantánea constituye la frontera de evidencia y vincula el resto del expediente con la
base exacta usada durante la generación.

La migración de datos incorpora el identificador de conexión al catálogo analítico y crea
la unicidad por fuente y dominio. Las API de metadatos, asistente, ETL y analítica validan
pertenencia antes de devolver o modificar un registro.

La pantalla muestra la instantánea utilizada y, para cada pregunta estándar, si existe
evidencia verificable. La configuración funcional nunca convierte una columna inexistente
en una capacidad. Una pregunta personalizada orienta al modelo, pero la propuesta debe
superar los mismos controles.

La revisión histórica confirmó que las cuatro preguntas iniciales ---tiempo, producto,
cliente y territorio--- fueron definidas por el perfil de ventas de la aplicación, no por
el LLM. En AdventureWorks el analista incorporó después dos preguntas personalizadas,
\textbf{Costos y rentabilidad de las ventas} y \textbf{Ventas y costos por unidad}, a partir
de recomendaciones conversacionales. WideWorldImporters no hereda esas personalizaciones:
parte de la línea base y sólo incorpora preguntas adicionales mediante una decisión humana.

\subsection{Selección semántica universal}

La búsqueda privilegia un subgrafo comercial coherente. Primero resuelve la tabla de hechos
y luego evidencia relacionada para fecha, producto, cliente, territorio y costo. Las
coincidencias exactas reciben prioridad sobre coincidencias parciales; compras, históricos,
auditoría y tablas temporales reciben penalización o exclusión según su función.

Las dimensiones solicitadas y respaldadas por evidencia se incorporan aunque el proveedor
las omita. Las medidas calculadas se reconstruyen con operaciones permitidas. Por ejemplo,
ventas puede derivarse de precio por cantidad y costo de cantidad por costo unitario, pero
sólo si ambas entradas existen y están conectadas mediante rutas verificadas.

\section{Ejecución y evidencia}

\subsection{Preparación de WideWorldImporters}

El contenedor descarga el respaldo oficial cuando no está presente, restaura la base de
forma idempotente y conserva el binario fuera de Git. El lector de demostración se agrega
a los roles existentes cuyo alcance es ventas. Esto permite que las políticas de seguridad
por territorio de la base de ejemplo no oculten clientes durante la prueba. Para fuentes
externas, el producto respeta los permisos definidos por el DBA y no los modifica.

\subsection{Propuesta y materialización}

La propuesta 96 se generó con Claude Haiku 4.5. El proveedor omitió inicialmente elementos
y propuso componentes incompatibles; el motor común incorporó dimensiones demostrables,
excluyó fórmulas sin evidencia y mantuvo como limitación el descuento no disponible. La
aprobación se realizó con cobertura completa de los requisitos viables.

AdventureWorks:

\subsection{Analítica}

El tablero obtiene filtros y rankings desde la ejecución seleccionada. La dimensión de
territorio conserva la clave, pero presenta nombres como Texas, Pennsylvania, California
y New York. Productos y clientes usan los atributos descriptivos materializados. La lista
de ejecuciones se filtra por fuente y expone conexión, base, propuesta y ejecución.

\section{Pruebas y riesgos}

\begin{tabularx}{\textwidth}{@{}p{0.27\textwidth}X@{}}

  Descubrimiento & Ventas actuales prevalecen sobre compras y archivos; auditoría no crea rutas de negocio. \\
  Proveedores & La validación posterior al LLM corrige omisiones y descarta referencias no demostrables. \\

  \bottomrule

El riesgo residual principal es que una fuente externa aplique seguridad por fila que
oculte datos al lector. Esto no se resuelve elevando privilegios desde la aplicación: debe
diagnosticarse y coordinarse con el DBA. También permanece fuera del alcance la traducción
automática de significados propios del negocio que no puedan demostrarse por metadatos.

\section{Revisión y retrospectiva}

El contraste entre dos modelos OLTP demostró que universalidad no significa reconocer
cualquier esquema sólo por semejanza léxica. Significa aplicar el mismo proceso de
descubrimiento, evaluación, propuesta, validación, materialización y trazabilidad, y detenerse
cuando falta evidencia.

El problema reportado en el catálogo permitió aclarar una responsabilidad clave: la IA no
es dueña del catálogo ni de la verdad técnica. Su aporte es interpretativo. La plataforma
mantiene el contrato y el analista conserva la decisión de negocio.
